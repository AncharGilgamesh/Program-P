# Ведение документации по практикам

Настольная программа кафедры ПМИ КНИТУ-КАИ. Она собирает план практик и отчёт из таблиц Excel и документов Word, даёт поправить строки на экране и хранит готовые файлы в локальной базе SQLite.

Окно называется **Project P**. Интерфейс на русском. Справка внутри программы лежит на вкладке «Руководство» и читается из [`help.html`](help.html).

## Что умеет программа

- Вход, регистрация и восстановление пароля. Пароль хранится как хеш bcrypt.
- Справочники преподавателей и старост.
- План практик: загрузка кафедральной таблицы, загрузка нагрузки, правка ячеек и сохранение в Word.
- Отчёт из шести таблиц, который собирается из сохранённого плана.
- Архив документов: открытие, защита от удаления и срок хранения 5 лет.

## Требования

- Windows 10 или новее. Открытие файла из базы на macOS и Linux тоже предусмотрено, основной сценарий проверялся на Windows.
- Python 3.11 или новее.
- [uv](https://docs.astral.sh/uv/) для установки зависимостей. Список пакетов зафиксирован в [`uv.lock`](uv.lock).

Основные библиотеки: PySide6, pandas, openpyxl, xlrd, python-docx, passlib и bcrypt. Версии указаны в [`pyproject.toml`](pyproject.toml).

## Установка и запуск

Из корня проекта:

```powershell
uv sync
copy .env.example .env
uv run python main.py
```

Перед регистрацией откройте `.env` и впишите код после знака `=`:

```text
REGISTRATION_CODE=код-кафедры
```

Файл `.env` в git не входит. Шаблон — [`.env.example`](.env.example). Программа читает `.env` при проверке и не затирает переменную, если она уже задана в системе. Пустой `REGISTRATION_CODE` закрывает регистрацию обычных имён и восстановление пароля: окно покажет «Регистрация недоступна: не задан код регистрации». Имя из `RESERVED_ADMIN` от кода не зависит. Пустой `RESERVED_ADMIN` отключает это исключение.

Проверка кода и тестов:

```powershell
uv run ruff check .
uv run pytest
```

## Первый запуск

Имя из **RESERVED_ADMIN** регистрируется всегда, даже при пустом коде и пустом справочнике преподавателей. В [`.env.example`](.env.example) это `admin`. Поменяйте значение, если нужно другое имя.

1. На экране входа откройте «Регистрация».
2. В имя пользователя впишите значение `RESERVED_ADMIN`. Регистр не важен: в базе сохранится написание из `.env`.
3. Задайте пароль и повтор. Код регистрации можно оставить пустым.
4. Фамилию, имя и отчество заполните. Если такой карточки ещё нет, программа создаст преподавателя с этими ФИО. Если карточка одна, учётка привяжется к ней. Если совпадений несколько, берётся первая.
5. Если такая учётка уже есть, окно попросит войти под этим именем. После удаления её можно зарегистрировать снова.

Дальше под этим пользователем откройте «База данных» → «Преподаватели» и добавьте остальных. Обычная регистрация по-прежнему требует код из `.env` и ровно одну карточку с тем же ФИО. Почту преподавателя можно оставить пустой. Две одинаковые заполненные почты база не примет. Почта старосты обязательна. Восстановление пароля по-прежнему спрашивает код регистрации.

Галочка «Запомнить меня» пишет только логин в `%USERPROFILE%\.magistr_project\remembered_username`. Пароль туда не попадает. Кнопка «Выйти» этот файл удаляет и возвращает окно входа.

В личном кабинете можно сменить пароль и удалить свою учётную запись. Карточка преподавателя при удалении учётки остаётся. Преподавателя, на которого ссылается староста или пользователь, удалить нельзя.

## Страницы

| Кнопка | Зачем |
| --- | --- |
| База данных | Документы, преподаватели, старосты |
| Генерация отчёта | Шесть этапов отчёта |
| План | Таблица плана практик |
| Руководство | Текст из `help.html` |
| Личный кабинет | Данные текущего пользователя |
| Выйти | Сброс «запомнить меня» и возврат ко входу |

Ячейки плана и отчёта редактируются прямо в таблице. Кнопки «Примечание», «Место проведения», «№ договора», «Необходимость закупки» и «Руководитель от предприятия» ставят одно значение сразу нескольким выбранным группам.

### План

- **Загрузить таблицу** — Excel с двумя листами. Первый лист читается как бакалавриат, второй как магистратура. Если таблица на экране уже заполнена, программа спрашивает, заменять ли план. Ответ «Нет» ничего не меняет.
- **Загрузить нагрузку** — широкая таблица нагрузки. По уже загруженному плану она только дописывает блок студентов в вид практики: `Г/б`, `Пл.` и `Целевики`. По пустой таблице строит план целиком.
- **Загрузить план** — ранее сохранённый Word плана.
- **Сохранить** — новый файл в `Saves` и строка в базе. Повторное нажатие не затирает прошлый файл.
- **Сохранить как** — Word в выбранную папку. В базу такая копия не записывается.

Файл «Загрузить таблицу» разбирается блоками. Новый блок начинается со строки, в первой ячейке которой есть «учебная практика» или «производственная практика», и кончается на пустой первой ячейке. Первая строка внутри блока считается шапкой. Из следующих строк берутся номер группы, ФИО преподавателя, направление и срок. Строка без группы пропускается. Пустое направление остаётся пустой ячейкой. Место проведения при этой загрузке заполняется словом «Кафедра», закупка — «нет».

В нагрузке первая строка считается шапкой. Дальше используются столбцы:

| Столбец Excel | Что читается |
| --- | --- |
| E | Номер группы |
| F | Бюджет, `Г/б` |
| G | Платное, `Пл.` |
| H | Всего студентов |
| I | Шифр специальности, первое слово ячейки |
| K | Уровень. Если в тексте есть «маг», строка идёт в магистратуру |
| M | Вид практики |
| N | Срок |
| Q | ФИО руководителя |
| AD | Примечание |

Целевики равны «всего» минус бюджет и платное. Если «всего» меньше суммы бюджета и платного, загрузка останавливается и называет группу. Вид практики приводится к одному из известных названий: ознакомительная, технологическая, эксплуатационная, научно-исследовательская работа и практика по получению навыков научно-исследовательской работы. Незнакомое название остаётся как в файле.

Пустая загрузка таблицы без блоков практики очищает сетку. Следующая нагрузка после этого снова строит план, а не пытается дописать студентов в пустую таблицу.

### Отчёт

Шесть этапов переключаются кнопками «Назад» и «Далее».

**Загрузить план** на странице отчёта читает Word плана и заполняет все шесть таблиц. **Загрузить отчет** читает уже сохранённый Word отчёта. Непустые таблицы заменяются только после подтверждения.

В таблицу оценок попадают группы, в тексте места которых есть номер вида `4xxx`, например `4411`. Строки без такого номера пропускаются, и программа сообщает их количество.

| Этап | Таблица | Кнопка на этапе |
| --- | --- | --- |
| 1 | Группа, направление, семестр, вид практики, дата собрания | «Назначить дату проведения собрания» |
| 2 | Город, место, направлено, прибыло, инструктаж, фактический конец | «Прибыли все» копирует направленных в прибывших |
| 3 | Место и два руководителя | «Один руководитель всем» ставит введённые фамилию и инициалы во все строки |
| 4 | Характер прохождения и отметка по технике безопасности | «Другое» переносит число прибывших из второго этапа |
| 5 | Оценки по группе | «Не защитило» считается само: всего минус сумма оценок. Ноль на экране показывается прочерком |
| 6 | Руководитель, должность, группа, вид практики и оценки | «Всем отл», «Всем хор», «Всем удовл» ставят плюс в один столбец |

Семестр на первом этапе считается по второй цифре номера группы и первому месяцу срока. Месяцы с июля по декабрь дают нечётный семестр, с января по июнь — чётный. Группа четвёртого курса в сентябре получает семестр 7.

При сборке из плана город ставится «Казань», кафедральное место собирается как учебная кафедра или лаборатория ПМИ, место защиты — «в КНИТУ-КАИ».

**Сохранить** пишет отчёт в `Saves` и в базу. **Сохранить как** только сохраняет выбранный файл.

## Где лежат данные

| Путь | Содержимое |
| --- | --- |
| `DB/maindatabase.db` | Пользователи, преподаватели, старосты и реестр документов. Файл создаётся при первом запуске, если его ещё нет |
| `Saves/` | Планы и отчёты, сохранённые кнопкой «Сохранить». Имя файла: год, `p` или `o`, дата и время |
| `Shablons/shablon_plan.docx` | Шаблон плана. Данные пишутся в первую таблицу со строки 2 |
| `Shablons/shablon_otchet.docx` | Шаблон отчёта. Шесть таблиц заполняются со строк 1, 2, 2, 2, 4 и 2 |
| `logs/app.log` | Время и трасса ошибок. Пароли туда не пишутся |
| `%USERPROFILE%\.magistr_project\` | Логин «запомнить меня» |

В базе хранится путь вида `Saves/имя.docx`. Если папку проекта перенесли целиком, программа находит файл в текущей `Saves` по этому пути или по имени. Файл вне `Saves` не открывается и с диска не удаляется. Если самого файла уже нет, удаление спрашивает, убрать ли только строку базы. Ответ по умолчанию — «Нет».

Документ с включённой защитой нельзя удалить ни кнопкой, ни проверкой срока. При первом открытии «Базы данных» за сеанс программа показывает документы старше пяти лет. Незащищённые можно удалить ответом «Да».

## Пример

Папка [`Example`](Example) содержит учебные файлы на три группы: `4111`, `4211` и `4411`.

| Файл | Куда загружать |
| --- | --- |
| `таблица_практик.xlsx` | План → «Загрузить таблицу» |
| `нагрузка.xlsx` | План → «Загрузить нагрузку» после таблицы |
| `план.docx` | План → «Загрузить план» или Отчёт → «Загрузить план» |
| `отчёт.docx` | Отчёт → «Загрузить отчет» |

`план.docx` собран так же, как кнопка «Сохранить» после таблицы и нагрузки. `отчёт.docx` собран из этого плана так же, как «Загрузить план» на странице отчёта. Повторить сборку: `uv run python Example/build_examples.py`.

## Структура проекта

```text
main.py                      окно и переключение страниц
window_support.py            пути, срок хранения, журнал, запись в Saves
help.html                    текст вкладки «Руководство»
pyproject.toml               зависимости и настройки ruff и pytest
.env.example                 шаблон кода регистрации

Models/dbhandler.py          SQLite: пользователи, преподаватели, старосты, документы
Models/datahandler.py        разбор Excel и Word
Models/docx_writer.py        запись строк в таблицы Word
Models/model.py              модели таблиц на экране

View/appearance.py           форма входа, собрана в Qt Designer
View/appearance_logic.py     вход, регистрация, чтение .env
View/workspace.py            главное окно, собрано в Qt Designer
View/plan_page.py            страница плана
View/report_page.py          страница отчёта
View/database_page.py        страница базы
View/planaddingdialogs.py    значение сразу нескольким группам
View/meetingdatedialog.py    дата собрания
View/prepod_dialog.py        карточка преподавателя
View/startosta_dialog.py     карточка старосты

tests/                       проверки разбора, учёток, документов и дат
Example/                     учебные Excel и Word
DB/                          база
Shablons/                    шаблоны Word
```

Файлы `View/workspace.py`, `View/appearance.py` и `View/res_rc.py` сгенерированы из форм Qt Designer. Их не форматируют и не правят вручную: изменения интерфейса делаются в `.ui`, затем форма пересобирается. Шаблоны в `Shablons/` программа ожидает в текущем виде.

Схема базы при запуске создаётся операторами `CREATE TABLE IF NOT EXISTS`. Отдельной миграции нет.

## Разработка

Тесты лежат в `tests/` и запускаются из корня:

```powershell
uv run pytest
uv run ruff check .
```

Ruff проверяет каталог целиком, кроме трёх сгенерированных файлов интерфейса. Каталоги `.venv`, `logs`, `.env` и кэши проверок в git не входят. Пример базы `DB/maindatabase.db` в репозитории остаётся: тесты учёток работают со своей временной базой и этот файл не переписывают.
